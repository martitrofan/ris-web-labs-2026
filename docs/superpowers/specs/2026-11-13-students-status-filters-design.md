# Design: страница статусов проверки (фильтры)

Дата: 2026-11-13  
Репозиторий: `ris-web-labs-2026` · маршрут `#/students`  
Статус: согласовано направление B+A; дефолт колонок — (3)

## Цель

Одна общая таблица статусов ЛР1–ЛР10 с фильтрами, без колонки «дата ревью» в таблице. Дата ревью — только в шапке. Таблица не должна раздуваться вширь по умолчанию.

## Не цели

- Публикация в GitHub до явного «залей»
- Issues / Google Sheet
- Изменение SoT приёмки в vault (кроме уже принятых статусов 12.11)

## UX

### Шапка

- Заголовок «Статус проверки»
- Строка: курс / семестр
- **Дата ревью** (одна на страницу)
- Легенда статусов: принято · доработать · не сдано · недоступен · нет в таблице
- Счётчик: «Показано N из M»

### Фильтры

| Фильтр | Тип | Поведение |
|--------|-----|-----------|
| ФИО | текст | подстрока, case-insensitive |
| Группа | select | все / ТРИС-1-23 / ТРИС-2-23 / ТРИС-3-23 |
| № ЛР | мультивыбор | какие **колонки** статусов показывать |

Пресеты у мультивыбора ЛР:

- **По умолчанию (3, уточнение при реализации):** включены ЛР, где есть хотя бы один статус **`доработать`** (строки целиком `недоступен` / `нет в таблице` не участвуют в расчёте).  
  Причина: если в дефолт входит массовое «не сдано», загораются сразу ЛР1–10 и ширина не выигрывается. Полный набор колонок — кнопкой «Все ЛР».
- **Все ЛР** — ЛР1…ЛР10
- **Сбросить** — вернуть дефолт (3)

Фильтр № ЛР **не** скрывает студентов; только колонки.  
ФИО + группа режут **строки**.

### Таблица (B + A)

Колонки всегда: `ФИО | Группа` + выбранные ЛР.

В ячейках ЛР — компактная метка (короткий текст / цветовой чип); полный статус — в `title` (tooltip).  
Непринятые статусы визуально сильнее.

Строки «нет в таблице» остаются в данных (группа из витрины), фильтруются как остальные.

Сортировка по умолчанию: группа, затем ФИО.

## Данные

- Источник витрины: `docs/students.json` (генерируется из `final_12.11.json` / vault-статусов при обновлении приёмки).
- Поля студента (минимум): `fio`, `group`, `labs: { lr1…lr10 }`, опционально `note`, `url`.
- Мета: `reviewDate`, `statuses` (легенда).

Markdown-таблицы по группам на `#/students` заменяются интерактивной страницей.  
`students.md` может остаться тонкой оболочкой (заголовок + mount-point) или редирект/HTML-вставка через Docsify plugin.

## Технический контур (высокий уровень)

1. Генератор JSON из текущего SoT приёмки (скрипт в workdir или в репо сайта).
2. `assets/students-board.js` + стили в `site.css`: фильтры, таблица, дефолт колонок.
3. Docsify: на маршруте students подключить board после загрузки контента.
4. Локальный `python -m http.server` для глазной проверки; push только после «залей».

## Критерии приёмки

- [ ] Дата ревью видна вне таблицы
- [ ] Одна таблица на все группы
- [ ] Фильтры ФИО, группа, № ЛР работают
- [ ] По умолчанию видны только «проблемные» ЛР (правило 3)
- [ ] Пресеты «Все ЛР» и «Сбросить» работают
- [ ] Компактные статусы + tooltip
- [ ] Ширина по умолчанию помещается на типичный desktop без горизонтального скролла при дефолтных колонках
- [ ] Без push до подтверждения
