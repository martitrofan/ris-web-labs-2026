## Зачем эта работа

Семестр сдаётся **ссылкой на репозиторий**, не архивом в почте. Преподаватель открывает GitHub, смотрит файлы и пишет замечания issue. Если ссылка 404 или репозиторий приватный без приглашения — в таблице статус «недоступен», работы как будто нет.

Представьте тетрадь, у которой каждая страница пронумерована и не стирается. Git — такая тетрадь для файлов. GitHub — шкаф в коридоре, куда преподаватель может подойти со своим ключом.

## Теория на пару

Если «что такое Git» не объясняли — 20–30 минут. Если объясняли — 5 минут и в методичку.

### 1. Зачем система контроля версий

**Система контроля версий (СКВ)** запоминает снимки проекта. Снимок называется **коммит**.

Без СКВ: `курсовая_финал_точно2.zip` на Рабочем столе и спор, какая копия свежая.  
С Git: видно, *когда* появился README и *что* в нём было вчера.

GitHub, GitLab, Codeberg — это **хостинги**. Они хранят копию репозитория в сети и дают issues. Сам учёт версий делает Git на компьютере.

### 2. Коммит

Вы меняете файлы → `git add` (что входит в снимок) → `git commit` (снимок с подписью) → `git push` (снимок уехал на GitHub).

Пока нет `push`, преподаватель видит старое. Это самая частая причина «я же исправил».

### 3. Issue

**Issue** — тикет в репозитории: «вот что не так по чеклисту». Студент чинит файлы, пишет комментарий, преподаватель закрывает issue, когда доработка принята. Закрывать чужое замечание самому рано.

### 4. Приватный репозиторий

Приватный репозиторий не виден случайным людям. Преподаватель тоже не увидит, пока вы его не пригласите. На GitHub: **Settings → Collaborators → Add people → `martitrofan`**. Дождитесь, пока преподаватель примет приглашение.

Подробные клики — в [методичке](/labs/00/method), раздел «Приватный репозиторий и приглашение преподавателя».

### 5. Чем GitHub можно заменить

Бесплатно: GitLab.com (преподаватель принимает), Codeberg — только если согласовали. Яндекс Диск и почта — не СКВ, преподаватель не принимает.
