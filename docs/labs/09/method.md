## Зачем вы здесь

Данные переезжают в настоящую базу. Пишете SQL: таблицы, связи, вставки, выборки. Серверный код на EF пока не обязателен — важно, что схема совпадает с вашей моделью из `/docs` и что после перезапуска Postgres запись на месте.

Секреты и пароли в Git не кладите.

## 1. Цель одной фразой

Схема PostgreSQL под ваш проект: таблицы со связями, четыре статуса, учебные данные и запросы с фильтром, сортировкой, `JOIN` и `GROUP BY`.

## 2. Что должно лежать в Git

### 2.1. Дерево файлов

```text
имя-репозитория/
├── README.md
├── db/
│   ├── schema.sql
│   ├── seed.sql
│   └── queries.sql
└── docs/
    └── reports/
        └── lab-09.md
```

В `/db` не должно быть дампа с локальными пользователями или паролями.

### 2.2. Что лежит в файлах

| Файл | Что внутри |
|---|---|
| `schema.sql` | справочник, пользователи, главный объект, PK, FK, CHECK, индексы |
| `seed.sql` | минимум 2 пользователя, 2 справочных строки, 4 статуса |
| `queries.sql` | фильтр, сортировка, JOIN, GROUP BY |

## 3. Проектирование схемы

### 3.1. Минимальные таблицы

1. Справочник вашей темы: участок, аудитория, тип услуги и т. п.
2. Пользователи: создатель и исполнитель.
3. Главный объект: заявка, бронь, обращение и т. п.

В главной таблице храните ссылку `site_id`, а не повторяющееся название участка.

### 3.2. Поля главного объекта

Ориентир:

```text
id
number
title
description
site_id
status
created_at
created_by_user_id
assignee_user_id
```

`assignee_user_id` допускает `NULL`: новая запись ещё не назначена.
Имена SQL пишите в `snake_case`.

### 3.3. Ограничение статусов

```sql
status text NOT NULL
  CHECK (status IN ('New', 'InProgress', 'Closed', 'Cancelled'))
```

Других значений быть не должно.
Не используйте `Done`, `NEW`, `Новая` или числа без согласованной модели.

### 3.4. Индексы

Обязательны:

```sql
CREATE INDEX tickets_status_idx ON tickets (status);
CREATE INDEX tickets_site_id_idx ON tickets (site_id);
```

Названия таблиц замените своими.
Рядом напишите комментарий, какой запрос ускоряет индекс.

## 5. Команды запуска

### 5.1. Через `psql`

```bash
createdb course_tickets
psql -d course_tickets -f db/schema.sql
psql -d course_tickets -f db/seed.sql
psql -d course_tickets -f db/queries.sql
```

Имя базы можно изменить.
Пароль вводите интерактивно или задавайте локально, но не записывайте в Git.

### 5.2. Через pgAdmin

1. Создайте учебную базу.
2. Откройте Query Tool.
3. Выполните `schema.sql`.
4. Выполните `seed.sql`.
5. Выполните `queries.sql`.
6. Сохраните скрин результата каждого обязательного запроса.

### 5.3. Повторный запуск схемы

Выберите один вариант:

- удалить и заново создать только учебную базу;
- в начале схемы удалить свои таблицы в правильном порядке;
- использовать `DROP TABLE IF EXISTS ... CASCADE` только для учебного пересоздания.

Не путайте пересоздание учебной схемы с `DELETE` в приложении.
В REST API курса `DELETE` по-прежнему не нужен.

## 6. Обязательные запросы

### 6.1. Фильтр и сортировка

```sql
SELECT number, title, status, created_at
FROM tickets
WHERE status = 'New'
ORDER BY created_at DESC;
```

### 6.2. JOIN

```sql
SELECT t.number, t.title, s.name AS site_name, t.status
FROM tickets AS t
JOIN sites AS s ON s.id = t.site_id
ORDER BY t.created_at DESC;
```

Результат обязан показывать название справочника, не только `site_id`.

### 6.3. GROUP BY

```sql
SELECT status, COUNT(*) AS count
FROM tickets
GROUP BY status
ORDER BY status;
```

Seed должен позволить увидеть все четыре группы.

### 6.4. Проверка CHECK

Попробуйте вставить строку со статусом `Done`.
PostgreSQL должен отказать по ограничению CHECK.
Не оставляйте ошибочную вставку в рабочем seed.

## 7. Частые ошибки

| Ошибка | Как исправить |
|---|---|
| Одна таблица содержит название участка | вынести справочник и хранить FK |
| Нет внешнего ключа | добавить `REFERENCES` |
| Статус — любой текст | добавить CHECK четырёх значений |
| В seed только `New` | добавить все четыре статуса |
| JOIN возвращает только id | выбрать имя из справочника |
| GROUP BY без COUNT | добавить агрегат |
| `siteId` создан в кавычках | использовать обычный `site_id` |
| Схема запускается только один раз | описать безопасное пересоздание |
| Пароль записан в README | удалить и сменить пароль |
| Вместо SQL показан EF | вернуться к трём SQL-файлам |
