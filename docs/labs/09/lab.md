### Зачем PostgreSQL, если есть список в C#

Список в памяти существует только до остановки процесса. PostgreSQL сохраняет данные на диск, поэтому записи доступны после перезапуска приложения.

SQL — язык запросов к СУБД. Это не C# и не JavaScript. Пример смысла запроса: выбрать из таблицы заявок те, что в работе, и показать название участка.

| Команда | Смысл |
|---------|--------|
| `CREATE TABLE` | Создать таблицу и определить столбцы |
| `INSERT` | Добавить строку |
| `SELECT` | Прочитать данные |
| `JOIN` | Соединить таблицы (например, заявка и название участка) |
| `GROUP BY` | Сгруппировать строки (например, сколько заявок в каждом статусе) |
| `CREATE INDEX` | Создать индекс для ускорения поиска по частому полю |

Как читать `SELECT`: *из какой таблицы* → *с чем соединить (`JOIN`)* → *какое условие* → *как упорядочить или сгруппировать* → *какие столбцы показать*.

### Ключи без учебника по базам

**Первичный ключ** — уникальный идентификатор строки. Двух заявок с одним `id` не будет.

**Внешний ключ** — ссылка на строку в другой таблице (например, заявка ссылается на участок с `id = 3`). Если такого участка нет, база не примет строку и сохранит согласованность данных.

**CHECK** — ограничение на допустимые значения. Для статуса — только четыре согласованных значения; `Done` или `новая` база отклонит.

**3НФ как в ЛР2:** название участка в таблице заявок не дублируйте. Храните только `site_id`.

Столбцы заявки в примере курса (свои имена — из ЛР2, смысл тот же):

`id`, `number`, `title`, `description`, `site_id`, `status`, `created_at` (тип `timestamptz` — момент с часовым поясом), `created_by_user_id`, `assignee_user_id`.

У новой заявки исполнитель пустой: в SQL это `NULL` (нет значения), не ноль и не пустая строка.

Приоритет не добавлять.

### Индекс

Индекс ускоряет выборки по индексированному полю. Если часто фильтруете по статусу `New`, индекс по `status` сокращает поиск. Если поле почти не используют в фильтрах (например, длинное описание), индекс обычно не нужен: он занимает место и замедляет вставки.

Обязательны два индекса: по статусу и по внешнему ключу справочника. Индекс по дате — по желанию.

`DELETE FROM tickets WHERE …` удаляет выбранные строки, таблица остаётся. `DROP TABLE tickets` удаляет таблицу целиком. В учебном скрипте `DROP` допустим только для пересоздания схемы с нуля, не как обычная операция приложения.

## Пример куска схемы (сокращённо)

```sql
CREATE TABLE sites (
  id    integer PRIMARY KEY,
  name  text NOT NULL
);

CREATE TABLE tickets (
  id                   integer PRIMARY KEY,
  number               text NOT NULL UNIQUE,
  title                text NOT NULL,
  site_id              integer NOT NULL REFERENCES sites (id),
  status               text NOT NULL CHECK (status IN ('New', 'InProgress', 'Closed', 'Cancelled')),
  assignee_user_id     integer NULL
);

CREATE INDEX tickets_status_idx ON tickets (status);
```

Это каркас, не полный файл. Добавьте пользователей, описание, даты — как в ЛР2.

Пример соединения и подсчёта:

```sql
SELECT tickets.number, sites.name, tickets.status
FROM tickets
JOIN sites ON sites.id = tickets.site_id
WHERE tickets.status = 'New'
ORDER BY tickets.created_at DESC;

SELECT status, COUNT(*) AS cnt
FROM tickets
GROUP BY status;
```

## Сдача

Схему можно повторно применить к учебной базе. Есть внешний ключ и CHECK. `JOIN` показывает имя справочника, а не только id. `GROUP BY` даёт сводку, полезную роли «руководитель» из ЛР1. На защите: зачем индекс по статусу; почему название участка не хранят текстом в заявке; чем `JOIN` отличается от `GROUP BY`.

## Частые ошибки

- Одна таблица «всё сразу» без справочника участков.
- Статус без CHECK — в базе появляются несогласованные значения вроде `new`, `NEW` и `Новая`.
- Пароль `postgres` в README или в Git.
- Вместо `queries.sql` сдан скрин работы через Entity Framework.
- В `JOIN` выбран только `site_id`, название участка не показано.
- В `seed` только статус `New` — на защите нечего показать в `GROUP BY`.
- В SQL использованы имена вроде `siteId` (camelCase). В PostgreSQL обычно `site_id`; иначе схема разъедется с моделью в ЛР10.
