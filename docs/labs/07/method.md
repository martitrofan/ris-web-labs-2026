```text

├── README.md                       ← запуск backend и ограничения ЛР7
├── .gitignore                      ← bin и obj
├── docs/
│   └── reports/
│       └── lab-07.md
├── frontend/                       ← остаётся, сегодня не меняется
└── backend/
    ├── backend.csproj
    ├── Program.cs
    ├── appsettings.json
    ├── appsettings.Development.json
    ├── Properties/
    │   └── launchSettings.json     ← HTTP-порт 5000
    ├── Controllers/
    │   └── ...                     ← контроллер-заготовка или файл из шаблона
    ├── Services/
    │   └── ...                     ← интерфейс/сервис-заготовка
    ├── Models/
    │   └── .gitkeep                ← либо модель-заготовка

        └── .gitkeep                ← либо заготовка контекста
```
Git не хранит пустые папки. Если `Models` или `Data` пока пусты, добавьте `.gitkeep` либо короткий README с назначением папки.
### 2.2. Адреса
| Адрес | Ожидаемый результат |
|-------|----------------------|
| `http://localhost:5000/swagger` | страница Swagger в Development |
| `http://localhost:5000/health` | `200` и `ok` / `Healthy` |
| `http://localhost:5000/info` | имя приложения и среда |
Если Swagger использует завершающий `/index.html`, запишите точный адрес в README.
### 2.3. README
Обязательный блок:
```bash
cd backend
dotnet restore
dotnet run
```
И обязательные факты:
- API: `http://localhost:5000`;
- Swagger: `http://localhost:5000/swagger`;
- данные заявок пока в памяти, после перезапуска пропадут;
- `/health` проверяет только живость процесса, а не создание заявки;
- настоящее создание появится в ЛР8.

Также не коммитьте локальные сертификаты, пароли и пользовательские настройки IDE.

## 3. Коротко по делу
### 3.1. C#, .NET и ASP.NET Core
- C# — язык файлов `.cs`;
- .NET — платформа и команда `dotnet`;
- ASP.NET Core — web-фреймворк, который принимает HTTP-запросы.
### 3.2. Контроллер и сервис
Контроллер принимает HTTP, вызывает сервис и формирует ответ. Сервис содержит правила. Контроллер не должен создавать сервис через `new`.
Главный ресурс курса будет реализован контроллером в ЛР8. Minimal API допустим для коротких служебных `/health` и `/info`.
### 3.3. DI
Dependency Injection (DI) означает: зависимость регистрируется в `Program.cs`, а контроллер получает её через конструктор.
Зачем: реализацию хранения можно заменить, не переписывая контроллер. Сегодня это заготовка; позже вместо списка в памяти появится PostgreSQL.
### 3.4. Swagger
Swagger показывает описанные HTTP-адреса и позволяет отправлять запросы без Vue. Он должен быть доступен в режиме Development.
### 3.5. `/health` не равно созданию
Ответ `200` на `/health` означает: процесс запущен и маршрут отвечает. Он не доказывает существование `POST /api/tickets`, проверку полей или сохранение данных.

## 4. Порядок на 4 часа

### Шаг A. Проверьте SDK
```bash
dotnet --version
git status
```
Нужен .NET 8 или новее, совместимый с аудиторией. Если есть только runtime, команда создания проекта не сработает: установите SDK.
### Шаг B. Создайте проект
Из корня репозитория:
```bash
dotnet new webapi -o backend --use-controllers
```
Если установленный шаблон не знает `--use-controllers`, создайте проект без флага и убедитесь, что контроллеры подключены. Не создавайте второй backend рядом.
### Шаг C. Запустите
```bash
cd backend
dotnet restore
dotnet run
```
Сначала устраните ошибки сборки. Только после успешного запуска меняйте маршруты.
### Шаг D. Проверьте Swagger
Откройте приложение в среде Development. В `Program.cs` должны быть подключены сервисы описания API и middleware Swagger/OpenAPI, соответствующие шаблону вашей версии.
Критерий готовности: браузер показывает интерактивный список endpoint по адресу из README.
Если `/swagger` даёт `404`, проверьте:
1. среда действительно Development;
2. сервис Swagger зарегистрирован;
3. middleware Swagger включён до запуска приложения;
4. адрес и порт совпадают с выводом терминала.
### Шаг E. Зафиксируйте порт
В профиле HTTP файла `Properties/launchSettings.json` задайте:
```text
http://localhost:5000
```
Перезапустите backend и убедитесь, что терминал пишет `Now listening on: http://localhost:5000`.
HTTPS-порт шаблона может остаться дополнительным, но проверка курса выполняется по HTTP 5000.
### Шаг F. Добавьте служебные адреса
`GET /health` возвращает короткий `200`-ответ: `ok` или `Healthy`.
`GET /info` возвращает минимум:
- имя приложения;
- среду `Development`;
- версию или учебную пометку ЛР7.
Не принимайте в `/health` поля `title`, `siteId`, `description`.
### Шаг G. Подготовьте слои
Создайте:
- `Controllers` — HTTP-контроллеры;
- `Services` — правила приложения;
- `Models` — модели запросов и ответов;
- `Data` — доступ к данным в следующих ЛР.
Добавьте простой интерфейс и сервис-заготовку либо документ назначения. Зарегистрируйте сервис в `Program.cs`. В отчёте напишите:
> Сервис зарегистрирован через DI, чтобы контроллер не создавал реализацию через `new`.
Полный CRUD не пишите. `DELETE` на курсе не используется; отмена позже будет статусом `Cancelled`.
### Шаг H. Проверьте запуск как сосед
1. Остановите сервер `Ctrl+C`.
2. Выполните команды README с начала.
3. Откройте Swagger.
4. Вызовите `/health`.
5. Убедитесь, что `/health` и Swagger — разные проверки.

## 5. Частые косяки

| Ошибка | Как исправить |
|--------|---------------|
| Backend создан внутри `frontend` | держать `/backend` рядом с `/frontend` |
| Swagger проверяют в Production | запускать Development и проверить middleware |
| Сервер слушает случайный 7xxx | настроить HTTP-порт 5000 |
| `/health` принимает данные заявки | оставить только проверку живости |
| `200 /health` называют готовым CRUD | явно указать, что POST появится в ЛР8 |
| Контроллер делает `new TicketService()` | зарегистрировать и внедрить сервис через DI |
| Пустые папки не попали в Git | добавить `.gitkeep` или README |
| В Git попали `bin` и `obj` | добавить исключения и убрать их из индекса |
| Сразу пишут весь CRUD | остановиться на каркасе и служебных адресах |
| Vue подключают сейчас | отложить fetch/CORS до интеграционной ЛР |
