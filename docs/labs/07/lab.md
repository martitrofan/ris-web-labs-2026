# Лабораторная работа (ЛР) 7. Каркас Web API


**Студенту на пару:** работать по [методичке](/labs/07/method) — шаги, Git и чеклист сдачи. Эту карточку читать, если нужна теория простыми словами.

4 ч. Тема лекций 10–11. Лекцию слушать не обязательно. После ЛР6. Начало текущего контроля (ТК) 3.


## Зачем эта работа

До сих пор «правду» про заявки придумывал браузер или мок. Два человека в двух вкладках легко получат разное. Сегодня появляется **общая** программа на компьютере: сервер. Пока он только запускается и отвечает «я жив». Создавать заявки по-настоящему — ЛР8.

Касса столовой снова: сегодня ставите кассу и табличку «открыто». Меню ещё не продаёте.

Клиент Vue сегодня **не** подключать. Не надо мучить CORS, пока нечего создавать.

Если ЛР6 не сдана — каркас всё равно поднимают. Стыковка будет в ЛР12.

## Цель

Папка `/backend` в том же репозитории, команда `dotnet run` открывает Swagger.

## Что сдать

- проект ASP.NET Core Web API (версия как в аудитории: .NET 8 или новее);
- страница Swagger в режиме разработки;
- адреса `/health` и `/info`;
- папки `Controllers`, `Services`, `Models`, `Data` — даже если внутри пока пусто или заготовка;
- в README корня: как запустить, порт **5000**, ссылка на Swagger, фраза «данные заявок пока в памяти, после перезапуска пропадут».

Папки `bin` и `obj` — мусор сборки, в Git не входят.

## Теория на пару

40 минут.

### Три слова, которые звучат одинаково

| Слово | Простыми словами | Как трогаете |
|-------|------------------|--------------|
| C# | Язык, на котором пишете | Файлы `.cs` |
| .NET | Платформа, которая это запускает | Команда `dotnet run` |
| ASP.NET Core | Надстройка: принимает HTTP из браузера | Проект Web API |

Можно знать C# и не уметь делать сайт. Можно запустить `dotnet` и не написать ни строчки API. На курсе нужны все три слоя, но сегодня достаточно запустить третий.

Зачем сервер, если Vue уже умеет `fetch`: номер заявки, статус `New` и запрет «короткая тема» должны быть **одинаковы** для всех. Это решает одна программа, не каждая вкладка.

### Как бежит запрос

Человек или Swagger стучится на `http://localhost:5000/health`. Дальше конвейер (pipeline):

1. запрос вошёл;
2. промежуточные обработчики (логирование, HTTPS-редирект — многое шаблон уже положил);
3. по пути поняли, какой метод вызвать;
4. контроллер (класс с кнопками-методами);
5. сервис (правила, позже — работа с базой);
6. ответ обратно.

**Контроллер** — тонкий: принял, вызвал сервис, вернул код. **Сервис** — «можно ли» и «что записать». Сегодня сервис может быть пустой заготовкой.

Главные заявки пишите контроллерами. **Minimal API** — короткий способ повесить один адрес без класса. Им можно сделать `/health` и `/info`, не заявки. Иначе на ЛР8 всё равно перенесёте в контроллер.

### Внедрение зависимостей (DI) без страшных слов

Плохо:

```csharp
public TicketsController()
{
    _service = new TicketService(); // сами создали
}
```

Хорошо: в `Program.cs` сказали «когда кому-то нужен TicketService, дай вот этот». Контроллер получает готовый объект в конструкторе. Зачем: на ЛР10 вместо списка в памяти подставите работу с PostgreSQL, контроллер не переписываете.

Для учебного списка в памяти на одно приложение хватит **одного** общего экземпляра (singleton): все запросы видят один список. Три умных слова singleton / scoped / transient сегодня не экзамен. Если запустили проект — уже хорошо.

`/health` отвечает: процесс не упал. Это как «кассир на месте». Это **не** значит, что создание заявки работает.

### Чеклист: `/health` ≠ создание заявки

Перед сдачей отметить. Если путаете на защите — работу возвращают к объяснению.

| Утверждение | да/нет |
|-------------|--------|
| `GET /health` возвращает что-то вроде `ok` / `Healthy` без тела заявки | |
| `/health` **не** принимает `title` / `siteId` / `description` | |
| Успешный `/health` **не** доказывает, что `POST /api/…` уже реализован | |
| Создание заявки появится в **ЛР8**, не сегодня | |
| В README явно: «данные заявок пока в памяти…» **и** «`/health` только живость процесса» | |
| Сосед по README открыл Swagger **и** отдельно дернул `/health` | |

На ТК3 преподаватель может спросить: «Сервер жив — заявка уже создаётся?» Правильный ответ: нет, пока нет контроллера/сервиса создания из ЛР8.

После `Ctrl+C` и нового `dotnet run` список в памяти пустой. Напишите это в README, чтобы на защите не удивлялись.

**Swagger** — веб-страница со списком ваших адресов и кнопкой «попробовать». Преподаватель на ТК3 часто смотрит её, а не ваш Vue.

Порт **5000** — как на схеме ЛР2. Если шаблон открыл 5xxx другой, поправьте `launchSettings.json` или явно напишите в README фактический порт и почему.

## Порядок на 4 часа

1. Проверка: `dotnet --version` печатает число. Нет — поставить SDK .NET.
2. В корне репозитория (рядом с `frontend` и `docs`):

   ```bash
   dotnet new webapi -o backend --use-controllers
   ```

   Если ваша версия шаблона ругается на флаг — `dotnet new webapi -o backend` и смотрите, появилась ли папка Controllers. Второй проект не плодить.

3. `cd backend`, `dotnet run`. Открыть в браузере `/swagger`. Если 404 — в `Program.cs` для Development должен быть `UseSwagger` / `MapSwagger`.
4. Добавить `/health` (текст `ok`) и `/info` (имя приложения, среда Development).
5. Создать четыре папки. Можно положить пустой `TicketsController` с одним тестовым `GET`.
6. Зарегистрировать пустой сервис в DI. В отчёт одно предложение: «регистрирую TicketService, чтобы контроллер не делал new».
7. Порт 5000, README, `.gitignore` с `bin/` и `obj/`.
8. Сосед по README запускает и видит Swagger и `/health`. Пройти чеклист «health ≠ создание».

## Сдача

Сосед запускает без вашей помощи. Swagger открывается. Чеклист `/health` заполнен. На защите: чем C# не ASP.NET Core; зачем DI, если можно `new`; чем `/health` не создание заявки (обязательный вопрос).

## Частые ошибки

- Проект создали внутри `frontend` — каша из npm и dotnet.
- Закоммитили `bin` — мусор и разные пути на чужой машине.
- Порт 7xxx, в схеме ЛР2 до сих пор 5000, никто не поправил документы.
- Начали писать весь CRUD сегодня и не успели запустить даже `/health`. Сначала дыхание, потом заявки.
- На защите путают «сервер отвечает 200 на /health» с «заявки уже сохраняются».
