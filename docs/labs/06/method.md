## Зачем вы здесь

Интерфейс отделяете от способа получения данных. Список и форма зовут функции API-модуля, умеют ждать ответ и показывают разные состояния человеку.

C# сегодня не пишете. Mock имитирует сервер. Порт будущего API уже фиксируете: `5000`.

Сдача — mock + `fetch`, четыре состояния списка, три разных отказа, защита от двойного клика, `.env` не в Git.

## 1. Цель одной фразой

Список и форма зовут API-модуль (mock или `fetch`), умеют ждать и показывают разные состояния. Двойной клик не плодит две записи; `id` и `number` приходят из ответа.

## 3. Коротко по делу
### 3.1. `fetch`
`fetch` встроен в браузер; axios не требуется.
```js
const response = await fetch(`${baseUrl}/api/tickets`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(body)
})
```
Коды `400` и `500` не вызывают `catch`. Проверяйте `response.ok`. В `catch` обычно попадает отсутствие ответа: неверный URL, сервер не запущен, сеть недоступна.
### 3.2. Mock
Mock повторяет форму серверного ответа, но живёт в JavaScript. Добавьте задержку около 500 мс, чтобы UI успел показать загрузку и заблокированную кнопку.
Mock нужен для работы без backend. В `tickets.js` держите один переключатель `USE_MOCK`, чтобы страницы не переписывались при смене источника.
### 3.3. Состояния UI
Для списка используйте одно значение:
```text
loading | empty | data | error
```
Не показывайте одновременно таблицу, загрузку и ошибку.
### 3.4. Блокировка повторной отправки
Перед запросом `isSubmitting = true`, в `finally` — `false`. Кнопка получает `:disabled="isSubmitting"`.

| D | 75–105 мин | Перевести список на асинхронную загрузку | работают loading, empty, data, error |
| E | 105–135 мин | Перевести форму на `createTicket` | результат берётся из ответа |

### Шаг A. Настройте адрес
Добавьте `.env` в `.gitignore`. Создайте `.env.example` с адресом порта `5000`. В `tickets.js`:
```js
const baseUrl = import.meta.env.VITE_API_BASE_URL
```
Не вставляйте URL отдельно в список и форму.
### Шаг B. Сделайте mock
Mock хранит учебный массив и возвращает объект с `ok`, `status`, `data`. Требования:
1. пауза примерно 500 мс;
2. короткий `title` → `400`;
3. учебный флаг `force500` → `500`;
4. нормальное создание → `201`;
5. успешный ответ содержит серверные `id`, `number`, `status: 'New'`.
Не возвращайте `TMP-1`, вычисленный страницей.
### Шаг C. Спрячьте источник данных
В `tickets.js`:
- при `USE_MOCK = true` вызовите mock и обработайте его как ответ;
- при `USE_MOCK = false` используйте `fetch`;
- для `!response.ok` создайте ошибку с HTTP-статусом;
- сетевую ошибку не подменяйте кодом `500`.
Функции должны вернуть данные или выбросить осмысленную ошибку. Страницы не импортируют `mockTickets.js`.
### Шаг D. Сделайте четыре состояния списка
При входе на `/`:
1. поставить `screen = 'loading'`;
2. вызвать `getTickets()` в `onMounted`;
3. пустой массив → `empty`;
4. непустой → `data`;
5. ошибка → `error`.
В template используйте взаимоисключающие `v-if` / `v-else-if` / `v-else`.
### Шаг E. Переведите форму на API
Форма продолжает проверять поля, затем вызывает:
```js
await createTicket({
  title,
  siteId: form.value.siteId,
  description: form.value.description
})
```
Созданный объект берите целиком из ответа. После успеха обновите общий список или заново вызовите загрузку, затем перейдите на `/`.
При отказе поля формы можно оставить заполненными, чтобы человек исправил ошибку.
### Шаг F. Защититесь от двойного submit
В начале обработчика:

```js
if (isSubmitting.value) return
isSubmitting.value = true
```

Снимите флаг в `finally`. На кнопке покажите «Создаём…» и отключите её.

### Шаг G. Воспроизведите три отказа

| Отказ | Как получить | Что проверить | Текст человеку |
|-------|--------------|---------------|----------------|
| 400 | `title` короче 5 символов | `!ok`, status 400 | «Проверьте поля» |
| 500 | включить учебный `force500` | `!ok`, status 500 | «Сервер не смог обработать запрос» |
| Нет связи | выключить mock и сломать URL/не запускать API | `catch`, ответа нет | «Нет связи с сервером» |

Не показывайте на все случаи «Ошибка 500».

### Шаг H. Проверьте Network

Откройте F12 → Network → Fetch/XHR.

- В режиме настоящего `fetch` запрос и статус должны быть видны.
- Если mock вызывается напрямую и HTTP-запроса нет, это ожидаемо: сделайте скрин кода/консоли и подпишите «mock без HTTP».
- Для сценария «нет связи» выключите mock: Network должен показать неуспешную попытку к порту `5000`.

В отчёте должен быть скрин успешного создания и хотя бы одного отказа либо согласованная преподавателем замена для прямого mock.

## 5. Частые косяки

| Ошибка | Как исправить |
|--------|---------------|
| 400 ожидают в `catch` | проверять `response.ok` и `status` |
| Любой отказ называют 500 | различать HTTP-ответ и отсутствие ответа |
| Забыли `await` | дождаться Promise до чтения данных |
| URL написан в двух страницах | оставить его только в API-модуле |
| Страница импортирует mock | импортировать `getTickets` / `createTicket` |
| `id` и `number` вычисляет форма | брать их из ответа |
| Все UI-состояния видны одновременно | использовать одно поле состояния |
| После ошибки кнопка навсегда disabled | снимать флаг в `finally` |
| Двойной клик создаёт две строки | ранний `return` и disabled |
| `.env` изменили без перезапуска Vite | перезапустить `npm run dev` |
| В Git попал `.env` | исключить, оставить `.env.example` |
