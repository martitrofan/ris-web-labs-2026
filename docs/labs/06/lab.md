В ЛР5 список жил в том же файле, что и форма. Настоящая система так не работает: список приходит **ответом на просьбу**. Сегодня учитесь просить. Своего сервера на C# ещё нет. ## Цель

Список и создание идут через `fetch`. Человек видит загрузку, пустой список, данные или ошибку — не всё сразу.

## Что сдать

- файл `.env` с строкой `VITE_API_BASE_URL=http://localhost:5000`;
- в Git только `.env.example` (тот же смысл, без секретов; секретов сегодня всё равно нет);
- модуль `src/api/tickets.js` (имя папки под ваш ресурс): функции `getTickets`, `createTicket`;
- мок `src/api/mockTickets.js`: пауза около полсекунды, на короткую тему ответ «как 400», на нормальную — «как 201»;
- на списке одно из четырёх состояний: грузится / пусто / есть строки / ошибка;
- разные тексты: «проверьте поля», «сервер сломался», «нет связи»;
- пока идёт создание, кнопка не нажимается второй раз.

Не делать: изменение, удаление, настройку CORS (мок живёт в том же приложении, браузер никуда на другой порт не ходит).

После успешного создания `id` и `number` взять **из ответа мока**, не придумать на клиенте. Иначе привычка останется, и в ЛР12 будут два разных номера.

## Теория на пару

### Что такое API здесь

**API** (application programming interface, программный интерфейс) — договор: какими просьбами пользоваться. На курсе просьбы — HTTP, ответы — JSON.

`fetch` — встроенная в браузер функция «сходи по адресу и принеси ответ». Её не надо ставить через `npm`. Axios не нужен.

```js
const response = await fetch(baseUrl + '/api/tickets', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    title: form.title,
    siteId: form.siteId,
    description: form.description
  })
})
```

Разбор по строкам:

- `await` — подожди, пока сеть ответит. Без него в `response` ещё пусто.
- `Content-Type` — «я прислал JSON», иначе сервер может не понять тело.
- `JSON.stringify` — объект JavaScript превратить в текст.

### Самая частая путаница: 400 не падает в `catch`

`fetch` считает ошибкой только «ответа не было»: выключили Wi-Fi, опечатались в адресе, сервер не запущен.

Если сервер ответил «400, тема короткая» — для `fetch` это **успешный приём ответа**. Нужно смотреть:

```js
if (!response.ok) {
  // 400, 404, 500 — сюда
}
```

`response.ok` истинно для кодов 200–299.

| Что случилось | Куда попадёте | Что написать человеку |
|---------------|---------------|------------------------|
| Тема из 2 букв | `ok === false`, status 400 | Проверьте поля |
| Мок вернул 500 | `ok === false`, status 500 | Сервер не смог обработать |
| Сломали URL нарочно | `catch` | Нет связи. Проверьте, что приложение запущено |

Не пишите на все случаи «ошибка 500».

### Четыре состояния экрана

Одновременно не бывает «и грузится, и таблица, и красная плашка». Заведите одно поле, например `screen: 'loading' | 'empty' | 'data' | 'error'`.

Иначе пустой массив выглядит как вечная загрузка, а человек жмёт ещё раз.

Пока идёт POST, кнопка `disabled`. Снимать блокировку в `finally` — и при успехе, и при ошибке. Иначе после сбоя кнопка навсегда мёртвая.

### Откуда адрес

Vite читает переменные из `.env`, если имя начинается с `VITE_`.

```
VITE_API_BASE_URL=http://localhost:5000
```

В коде:

```js
const baseUrl = import.meta.env.VITE_API_BASE_URL
```

После правки `.env` **перезапустите** `npm run dev`. Иначе старое значение.

Сегодня мок можно вызывать всегда. Адрес всё равно пропишите: привычка и заготовка к ЛР12. Переключатель `USE_MOCK = true` в одном файле.

Вкладка **Network** в инструментах разработчика (F12) показывает, ушёл ли запрос. Для мока внутри приложения запроса на порт 5000 может не быть — это нормально. Тогда:

1. в моке вызывайте настоящий `fetch` на учебный путь (например тот же `/api/tickets` через относительный URL или через временный обработчик), **или**
2. включите в Network фильтр Fetch/XHR и покажите запрос, который реально уходит из `createTicket`, **или**
3. если мок без сети — в отчёте скрин консоли/`debugger` + явная пометка «мок без HTTP»; на защите всё равно открыть Network и объяснить, *где* появится запрос после ЛР12.

На сдаче **обязателен скрин Network** (или согласованная замена из пункта 3) хотя бы для одного успешного создания и для одного отказа.

### Чеклист трёх отказов (сдать в отчёте)

| Отказ | Как воспроизвести | Что в Network / коде | Текст человеку | Скрин есть |
|-------|-------------------|----------------------|----------------|------------|
| 400 | тема короче 5 символов | статус 400, ветка `!response.ok` | Проверьте поля | да / нет |
| 500 | учебный флаг мока «верни 500» | статус 500, ветка `!response.ok` | Сервер не смог | да / нет |
| Нет связи | сломать URL / выключить мок так, чтобы `fetch` упал | срабатывает `catch` | Нет связи… | да / нет |

Три строки — три разных текста. Нельзя подписать все случаи «ошибка 500».

## Пример каркаса мока

```js
const delay = (ms) => new Promise((resolve) => setTimeout(resolve, ms))

export async function mockCreate(body) {
  await delay(500)
  if (!body.title || body.title.length < 5) {
    return { ok: false, status: 400, data: { title: 'Слишком короткая тема' } }
  }
  return {
    ok: true,
    status: 201,
    data: { id: 17, number: 'A-117', status: 'New', ...body }
  }
}
```

Экран берёт `id` и `number` из `data`, не считает сам.

## Сдача

Двойной клик не создаёт две строки. В отчёте — чеклист 400 / 500 / нет связи и скрин Network. Студент словами объясняет три разных отказа. На защите: почему 400 не в `catch`; что остаётся в полях после отказа (форму не обязательно очищать); куда на ЛР12 подставят `http://localhost:5000`.

## Частые ошибки

- `await` забыли — в списке `Promise`, таблица пустая.
- Все ошибки ловят только `catch` — 400 никогда не показывают как «поля».
- После POST рисуют номер «TMP-1» сами — на живом API разъедется.
- `.env` закоммитили вместе с будущим паролем. Сегодня пароля нет, привычку не заводить: в Git пример.
- Не перезапустили Vite — `baseUrl` равен `undefined`, адрес «undefined/api/tickets».
