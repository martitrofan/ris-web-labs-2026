## 1. Анализ и требования

- Предметная область и зачем автоматизировать процесс.
- Роли и граница MVP / что вынесено в запас ВКР.
- Ссылка на `/docs/lab-01-requirements.md` и `/docs/project-proposal.md`.
- Три обязательных критерия приёмки (дано / когда / тогда).

**Артефакты:** пути к файлам ТЗ и заявки на тему.

## 2. Проектирование и архитектура

- Три узла: Vue (:5173) → ASP.NET Core (:5000) → PostgreSQL.
- Подпись: «это архитектура web-ИС семестра».
- ER: сущности, PK/FK, четыре статуса, назначение ≠ статус.
- Черновик REST (свои пути из таблицы соответствия).

**Артефакты:** схема в `/docs`, ER, таблица API из ЛР2.

## 3. Клиентская часть (UI)

- Стек: Vue 3 + Vite, JavaScript (не TypeScript), vue-router.
- Три экрана: список, создание, вход.
- Клиентская проверка полей; `fetch`; состояния загрузка / пусто / данные / ошибка.
- Семантика: `main`, `form`, `label` (оценка за «красивый макет» не цель).

**Артефакты:** `frontend/…`, скрины, при необходимости Network.

## 4. Сервер и программный интерфейс (API)

- Контроллеры, DTO, тонкий контроллер, сервис.
- Коды 200 / 201 / 400 / 404 / 409.
- Два PATCH: assignee и status.
- Коллекция запросов ЛР8.

**Артефакты:** `backend/…`, `/docs/api-collection/`, пример успешного и отказного ответа.

## 5. База данных

- PostgreSQL; 3НФ на справочнике; CHECK статусов.
- EF Core, миграции в Git.
- Доказательство: после рестарта API запись на месте.
- Секрет подключения не в репозитории.

**Артефакты:** `/db`, папка Migrations, сценарий рестарта.

## 6. Безопасность и тестирование

- Authn / authz; 401 без входа; 403 на чужой объект.
- Hash пароля; матрица ролей в `/docs`.
- XSS: пользовательский текст не как HTML.
- Позитив и негатив по трём критериям ЛР1.

**Артефакты:** `role-matrix.md`, скрины 401/403, `.gitignore`.

## 7. Поставка и вывод

- README как деплой-минимум (локальный контур, не облако).
- Какие требования выполнены; известные ограничения; запас под ВКР.

**Артефакты:** корневой `README.md`, чек-лист ЛР12–13.
