## 4. Приоритет дефектов

Исправляйте строго сверху вниз:

1. Стенд не запускается по README.
2. Не выполняется создание, назначение или `InProgress`.
3. Нет сохранения после рестарта.
4. Ошибочный код: 500 вместо 400/404/409.
5. Нарушение доступа: нет 401/403.
6. Ошибка документации.
7. Косметика.

Не тратьте время на отступы,
пока сосед не может применить миграции.

## 5. Карточка дефекта

Для каждого найденного дефекта заполните:

```markdown
## D-01. Короткое название
- Шаги / ожидали / получили:
- Причина и исправление:
- Повторная проверка:
- Статус: открыт / закрыт
```

Статус `закрыт` ставьте только после повторного прогона.
Фраза «исправил код» без проверки недостаточна.

## 7. План демо на 7 минут

### 0:00–0:30 — контекст

- назвать заказчика;
- назвать главный объект;
- сказать, какой сценарий будет показан.

### 0:30–4:30 — основной путь

1. Войти принимающим.
2. Создать объект через UI.
3. Показать `201` и `id` в Network.
4. Показать тот же `id` в SQL.
5. Назначить исполнителя.
6. Войти исполнителем.
7. Перевести тот же объект в `InProgress`.

### 4:30–6:30 — защита и сохранность

1. Показать POST без входа → `401`.
2. Показать чужой объект → `403`.
3. Перезапустить API.
4. Показать, что запись сохранилась.

### 6:30–7:00 — завершение

- назвать один известный предел;
- остановиться;
- принять вопросы.

Не начинайте демо с установки Node или листания исходников.
