# Лабораторная работа (ЛР) 4. Vue: компоненты и маршруты


**Студенту на пару:** работать по [методичке](/labs/04/method) — шаги, Git и чеклист сдачи. Эту карточку читать, если нужна теория простыми словами.

4 ч. Тема лекции 06. Лекцию слушать не обязательно. После ЛР3.


## Зачем эта работа

В ЛР3 всё жило в одном `App.vue`. К курсовой там будут шапка, таблица, форма, вход — файл станет нечитаемым. Сегодня режете экран на куски и даёте каждому куску адрес, как у страниц сайта: `/` список, `/new` форма, `/login` вход.

Если ЛР3 не открывается через `npm run dev` — сначала чините каркас. Маршруты на мёртвом проекте не ставят.

## Цель

Компоненты + адреса в строке браузера.

## Что сдать

- отдельные файлы: шапка, список (таблица), форма — минимум;
- таблица **получает** массив снаружи и сама его не выдумывает;
- три адреса: `/`, `/new`, `/login`;
- меню из ссылок `router-link`, не из трёх кнопок `v-if`.

Страница одной заявки `/tickets/17` не обязательна. Цвет кнопок не проверяют, если видно меню и поля.

## Теория на пару

35–45 минут.

### Компонент — кусок экрана в своём файле

Как разделы в тетради: «шапка», «таблица», «форма». Каждый в файле `.vue`.

Таблица умеет только рисовать то, что ей дали. Она не хранит «свой» секретный список. Иначе форма добавит заявку в один список, а таблица смотрит в другой — на экране пусто.

**Props** (пропсы) — данные *вниз*, от родителя к куску. Как передать список в таблицу:

```vue
<TicketTable :items="items" />
```

Внутри таблицы:

```js
defineProps({
  items: { type: Array, required: true }
})
```

**Emit** — сообщение *вверх*. Таблица не создаёт заявку сама. Она может сказать: «нажали на строку 17». Форма скажет: «хотят создать». Решает тот, кто владеет массивом.

Бытовая аналогия: официант (таблица) не решает меню кухни. Он приносит блюда, которые ему дали, и кричит на кухню: «стол 4 просит счёт».

### Адрес экрана и адрес API — не одно и то же

| Что | Пример | Смысл |
|-----|--------|--------|
| Маршрут Vue | `http://localhost:5173/new` | Какой экран показать человеку |
| Путь API | `POST http://localhost:5000/api/tickets` | Просьба к серверу |

Сервера ещё нет. Но уже нельзя называть `/new` «запросом». На схеме ЛР2 это разные стрелки.

`router-view` — дырка в `App.vue`, куда Vue подставляет текущий экран. Шапка обычно снаружи, чтобы не копировать меню три раза.

```html
<AppHeader />
<router-view />
```

### Картинка: шапка снаружи, страница внутри

Скопируйте в отчёт или перерисуйте. Смысл: меню не живёт внутри списка/формы/входа.

```text
┌─────────────────────────────────────────────┐
│  App.vue                                    │
│  ┌───────────────────────────────────────┐  │
│  │  AppHeader  (router-link: /  /new  /login)
│  └───────────────────────────────────────┘  │
│  ┌───────────────────────────────────────┐  │
│  │  <router-view />                      │  │
│  │     сейчас один из экранов:           │  │
│  │     • TicketList   путь /             │  │
│  │     • TicketNew    путь /new          │  │
│  │     • Login        путь /login        │  │
│  └───────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
```

Если шапку положить только в экран списка, на `/new` меню пропадёт. Если скопировать шапку в три файла — правка пункта меню делается трижды.

Меню:

```html
<router-link to="/">Список</router-link>
<router-link to="/new">Создать</router-link>
<router-link to="/login">Вход</router-link>
```

Проверка: введите в адресной строке `http://localhost:5173/new` и нажмите Enter. Должна открыться форма, не белая страница и не список. Если белая — роутер не подключён или нет маршрута. Шапка при этом остаётся на месте.

### Куда деть массив заявок

Список на `/`, форма на `/new`. Если массив объявлен только внутри экрана списка, вы ушли на форму, вернулись — массив родился заново, пустой.

Держите массив в **одном** файле, например `src/ticketsStore.js`:

```js
import { ref } from 'vue'

export const items = ref([
  { id: 1, number: 'A-101', title: 'Насос', siteId: 2, status: 'New' }
])
```

Оба экрана делают `import { items } from './ticketsStore.js'`. Pinia (отдельная библиотека хранилищ) не нужна.

## Как подключить роутер, если его не ставили в ЛР3

```bash
cd frontend
npm install vue-router
```

Файл `src/router.js`:

```js
import { createRouter, createWebHistory } from 'vue-router'
import TicketList from './pages/TicketList.vue'
import TicketNew from './pages/TicketNew.vue'
import Login from './pages/Login.vue'

export const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/', component: TicketList },
    { path: '/new', component: TicketNew },
    { path: '/login', component: Login }
  ]
})
```

В `main.js` должно быть что-то вроде `app.use(router)`.

Имена файлов свои, смысл тот же: три страницы, три пути.

## Порядок на 4 часа

1. Поставить `vue-router`, если его нет.
2. Создать три страницы-компонента, перенести туда разметку из ЛР3.
3. Прописать маршруты, подключить в `main.js`.
4. Шапка с `router-link` в `App.vue`, ниже `router-view`.
5. Таблицу вынести в свой файл, передать `:items="items"`.
6. Массив — в общий модуль.
7. Проверить три адреса руками в строке браузера, не только кликами.
8. В отчёт: скрин адресной строки на `/new`, список файлов `.vue`, картинка или своя схема «шапка снаружи / router-view внутри».

## Сдача

Три адреса открывают разные экраны. Шапка не пропадает при смене маршрута. Таблица не содержит собственного массива. На защите: чем `/new` не `POST /api/tickets`; кто владеет списком; что будет, если массив оставить внутри списка; зачем шапка снаружи `router-view`.

## Частые ошибки

- Кнопки с `v-if` вместо роутера — адрес не меняется, работу не засчитывают.
- Таблица скопировала массив в себя через `ref([...props.items])` и забыла родителя.
- Обновили страницу на `/new` — 404 от Vite. Для учебного проекта обычно хватает `createWebHistory` и dev-сервера Vite; если 404, скажите преподавателю, разберёте `base`.
- Поставили Pinia «как во всех туториалах» — на курсе лишнее.
