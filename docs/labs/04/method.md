## 3. Коротко по делу
### 3.1. Компонент и страница
Компонент решает одну задачу: шапка показывает меню, таблица рисует строки. Страница собирает компоненты для конкретного маршрута.
`router-view` — место, куда роутер подставляет страницу текущего адреса.
### 3.2. Props
Props передают данные от владельца вниз:
```vue
<TicketTable :items="items" />
```
В `TicketTable.vue`:
```js
defineProps({
  items: { type: Array, required: true }
})
```
Таблица не создаёт собственный `ref` с копией элементов и не меняет полученный массив.
### 3.3. Общее состояние без Pinia
Один учебный модуль:
```js
import { ref } from 'vue'
export const items = ref([
  { id: 1, number: 'A-101', title: 'Насос', siteId: 2, status: 'New' }
])
```
Этого достаточно. Pinia не требуется.
### 3.4. Два разных адреса
- `/new` — маршрут внутри Vue, показывает страницу.
- `POST /api/tickets` — будущий HTTP-запрос на сервер.
Маршрут не создаёт запись сам.

### Шаг A. Зафиксируйте рабочую точку
```bash
cd frontend
npm install
npm run dev
```
Если ЛР3 не запускается, сначала верните рабочие три экрана. Не подключайте роутер к сломанному каркасу.
### Шаг B. Подключите роутер
Если роутер не был выбран при создании:
```bash
npm install vue-router
```
В `main.js` импортируйте `router` и вызовите `app.use(router)` до `mount`.
### Шаг C. Создайте маршруты
Минимальный `router.js` содержит:
```js
const routes = [
  { path: '/', component: TicketList },
  { path: '/new', component: TicketNew },
  { path: '/login', component: Login }
]
```

Используйте `createRouter` и `createWebHistory`. Перенесите разметку экранов из ЛР3 в три страницы.

Проверка:

1. Введите `/new` руками.
2. Обновите страницу.
3. Введите `/login`.
4. Вернитесь на `/`.

### Шаг D. Вынесите шапку

В `AppHeader.vue` используйте:

```html
<router-link to="/">Список</router-link>
<router-link to="/new">Создать</router-link>
<router-link to="/login">Вход</router-link>
```

В `App.vue` оставьте только каркас:

```html
<AppHeader />
<router-view />
```

Шапка не должна находиться внутри `TicketList.vue`.

### Шаг E. Вынесите таблицу

`TicketList.vue` владеет ссылкой на `items` и передаёт её:

```html
<TicketTable :items="items" />
```

`TicketTable.vue` объявляет props и рисует строки. В нём нет тестового массива и нет `ref([...props.items])`.

### Шаг F. Создайте общий store

Перенесите массив из страницы в `src/ticketsStore.js`. Импортируйте один и тот же `items` там, где он нужен.

Это не серверное хранение. После F5 модуль создаётся заново — в ЛР5 это останется ожидаемым поведением.

### Шаг G. Подготовьте доказательства

В отчёт добавьте:

1. скрин `/new` с адресной строкой;
2. дерево `src/`;
3. схему «AppHeader снаружи, router-view внутри»;
4. короткую фразу: «таблица получает массив через props, источник — ticketsStore.js».

## 5. Частые косяки

| Ошибка | Как исправить |
|--------|---------------|
| Остались кнопки и `v-if`, URL не меняется | заменить на `router-link` и маршруты |
| Шапка скопирована в каждую страницу | оставить один `AppHeader` в `App.vue` |
| Шапка находится внутри `router-view` | вынести выше него |
| Таблица содержит свой тестовый массив | передать `items` через props |
| Props копируются в `ref([...props.items])` | рисовать входные props напрямую |
| Массив объявлен в `TicketList.vue` | перенести в `ticketsStore.js` |
| `/new` называют API-запросом | различать маршрут Vue и POST API |
| Установлен Pinia | удалить лишнюю зависимость, если она нигде не нужна |
| Прямой ввод `/new` даёт белый экран | проверить router, импорт страницы и `app.use(router)` |

2. Три адреса открывают три страницы.
3. Один `AppHeader` остаётся видимым на всех страницах.
