## Зачем вы здесь

Форма создания наконец что-то делает: кладёт запись в общий массив. Сервера нет — список живёт только в памяти браузера.

Сдача — работающая форма, отказ по правилам, коммит и чеклист.

## 1. Цель одной фразой

Связать форму с общим массивом: нормальная отправка добавляет `New`, короткая тема — отказ, F5 очищает память. Браузер при Enter не перезагружает страницу.

## 3. Коротко по делу
### 3.1. `ref` и `.value`
В `<script setup>` содержимое `ref` читают через `.value`. В `<template>` Vue разворачивает его автоматически.
```js
const form = ref({
  title: '',
  siteId: 0,
  description: ''
})
```
```html
<input v-model="form.title">
```
### 3.2. `v-model` и числа
`v-model` связывает поле с состоянием. Для внешнего ключа нужен модификатор:
```html
<input type="number" v-model.number="form.siteId">
```
Без `.number` значение часто становится строкой.
### 3.3. `submit.prevent`
Обычная HTML-форма перезагружает страницу. Для Vue:
```html
<form @submit.prevent="onCreate">
```
Теперь Enter и кнопка вызывают `onCreate`, не уничтожая состояние приложения.
### 3.4. Проверка на клиенте
Минимальные правила курса:
- `title`: 5–80 символов после `trim`;
- `siteId`: целое число больше нуля;
- `description`: 10–500 символов.
Клиентская проверка помогает человеку, но не заменяет серверную проверку ЛР8.

### Шаг A–B. Свяжите поля
В `TicketNew.vue` объявите форму и ошибки. У каждого поля сохраните `label` и `id`.
```html
<input id="title" v-model="form.title" autofocus>
<input id="siteId" type="number" v-model.number="form.siteId">
<textarea id="description" v-model="form.description"></textarea>
```
Под полями предусмотрите элементы для сообщений об ошибках.
### Шаг C. Проверьте тип `siteId`
Временно выведите в интерфейсе или консоли:
```js
typeof form.value.siteId
```
После ввода числа результат должен быть `number`. Удалите временный вывод перед сдачей.
Форму отправляйте только через:

```html
<form @submit.prevent="onCreate">
```

### Шаг D. Отклоните короткую тему

В начале `onCreate`:

1. получите `form.value.title.trim()`;
2. проверьте длину;
3. запишите понятную ошибку;
4. сделайте `return` до добавления.

Один пробел также должен быть отклонён. Текст ошибки, например: «Тема: от 5 до 80 символов».

Проверьте также `siteId > 0` и длину описания. Ошибка должна быть рядом с соответствующим полем.

### Шаг E. Добавьте запись в общий store

В `ticketsStore.js` храните:

- `items`;
- следующий учебный `id`;
- функцию `addItem`.

Новая запись получает:

```js
{
  id: nextId,
  number: `TMP-${nextId}`,
  title,
  siteId,
  description,
  status: 'New'
}
```

Не создавайте второй массив внутри формы или таблицы.

### Шаг F. Завершите успешный сценарий

После добавления:

1. очистите ошибки;
2. сбросьте поля;
3. выполните `router.push('/')`;
4. проверьте новую строку в таблице.

Если строка не видна, проверьте, что форма и список импортируют один `items` из одного файла.

## 5. Частые косяки

| Ошибка | Как исправить |
|--------|---------------|
| `form.title` используется в script | писать `form.value.title` |
| `form.value.title` написано в template | писать `form.title` |
| Нет `.prevent` | добавить `@submit.prevent="onCreate"` |
| `siteId` равен строке `"2"` | применить `v-model.number` |
| Проверяется только `if (title)` | использовать `trim()` и длину 5–80 |
| Короткая тема показывает ошибку, но всё равно добавляется | поставить `return` до `addItem` |
| Статус берётся из поля пользователя | всегда задавать `New` |
| Массив продублирован в форме | использовать общий `ticketsStore.js` |
| После F5 пропало — считают багом | это ожидаемо до API и БД |
| Использован `v-html` для темы | выводить через `{{ }}` |
