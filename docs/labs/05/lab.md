# Лабораторная работа (ЛР) 5. Vue: форма и список в памяти


**Студенту на пару:** работать по [методичке](/labs/05/method) — шаги, Git и чеклист сдачи. Эту карточку читать, если нужна теория простыми словами.

4 ч. Тема лекций 07 и начала 08. Лекцию слушать не обязательно. После ЛР4.


## Зачем эта работа

До сих пор форма была картинкой. Сегодня нажатие «Создать» добавляет строку в список. Сервера нет: список живёт в оперативной памяти вкладки. Нажали F5 (обновить страницу) — список снова из заготовки или пустой. Это **нормально**. В базу данные попадут только в ЛР10. В отчёте так и напишите: «после F5 пропало, ждали».

## Цель

Форма пишет в общий массив. Короткая тема в таблицу не попадает.

## Что сдать

- поля формы связаны через `v-model`;
- отправка формы не перезагружает страницу (`@submit.prevent`);
- успешная запись видна в списке без правки кода руками;
- участок (`siteId` или ваш ключ справочника) — **число**, не строка `"2"`;
- у новой записи статус `New`;
- если тема пустая или короче 5 символов — строка не добавляется, под полем текст ошибки.

В отчёте можно приложить таблицу «script / template» из теории (или свою). `id` и `number` пока выдумываете сами (счётчик 3, 4, 5…). Настоящие номера с сервера появятся в ЛР6.

В отчёт три доказательства: успех, отказ короткой темы, F5 очистил список.

## Теория на пару

35–45 минут.

### `ref` — коробочка, за которой следит Vue

Обычная переменная `let title = ''` Vue не интересует. `ref` — коробочка: положили новое значение, экран обновился.

В **скрипте** достают содержимое через `.value`:

```js
import { ref } from 'vue'

const form = ref({
  title: '',
  siteId: 0,
  description: ''
})

form.value.title = 'Насос встал'
```

В **шаблоне** `.value` не пишут. Vue сам разворачивает коробочку:

```html
<p>Сейчас в теме: {{ form.title }}</p>
```

Если в шаблоне написать `form.value.title`, будет путаница или ошибка. Запомните: точка `value` — только в `<script>`.

### Что писать в `script`, что в `template`

Держите под рукой на пару. Путаница здесь — главная причина «у меня форма пустая».

| Задача | Пишут в `<script setup>` | Пишут в `<template>` |
|--------|--------------------------|----------------------|
| Объявить форму и список | `const form = ref({…})`, `import { items } from '…'` | — |
| Прочитать/записать поле | `form.value.title`, `items.value.push(…)` | `{{ form.title }}`, `v-model="form.title"` |
| Отправить форму | `function onCreate() { … }` | `<form @submit.prevent="onCreate">` |
| Показать ошибку | `const error = ref('')` | `{{ error }}` под полем |
| Уйти на список | `router.push('/')` | иногда `<router-link>`, для после создания — из скрипта |
| Цикл по заявкам | массив уже в модуле/ref | `v-for="t in items" :key="t.id"` |
| Условие «показывать блок» | флаг в `ref`, если нужен | `v-if="…"`, `v-else` |

Кратко: **логика и `.value` — в script; разметка и директивы без `.value` — в template**.

### `v-model` — поле и коробочка ходят парой

Человек печатает в `<input>` — значение в `form` меняется. Поменяли в скрипте — поле на экране тоже меняется.

```html
<label for="title">Тема</label>
<input id="title" v-model="form.title" />
```

Для числа:

```html
<input id="siteId" type="number" v-model.number="form.siteId" />
```

Без `.number` в `siteId` часто оказывается строка `"2"`. Потом на сервере проверка «это целое?» упадёт.

### Почему страница прыгает и список умирает

Обычный HTML-`<form>` при Enter делает то, что умеет браузер с 1990-х: отправить форму на сервер и **перезагрузить** страницу. Vue-приложение родится заново, массив пустой.

Пишут так:

```html
<form @submit.prevent="onCreate">
```

`.prevent` значит: не делай стандартную перезагрузку, вызови нашу функцию `onCreate`.

### Проверка на клиенте — вежливость, не защита

Правила курса (если в ЛР1 не обосновали другие):

- тема от 5 до 80 символов;
- описание от 10 до 500;
- номер справочника — целое больше нуля.

Вынесите проверку в функцию. Если не ок — `addItem` не вызывать, под полем показать «Тема слишком короткая».

На ЛР8 те же правила повторит сервер. Почему дважды: форму можно обойти через инструменты разработчика и послать запрос напрямую. Клиент бережёт человека от опечатки, сервер бережёт данные.

Текст заявки на экране только через `{{ title }}`. Не вставляйте его как HTML: если кто-то в теме напишет скрипт, он не должен выполниться.

## Пример функции создания

Имена свои, смысл такой.

```js
function onCreate() {
  const title = form.value.title.trim()
  if (title.length < 5 || title.length > 80) {
    error.value = 'Тема: от 5 до 80 символов'
    return
  }
  items.value.push({
    id: nextId++,
    number: 'TMP-' + nextId,
    title,
    siteId: form.value.siteId,
    description: form.value.description,
    status: 'New'
  })
  error.value = ''
  form.value = { title: '', siteId: 0, description: '' }
  router.push('/')
}
```

`items` — тот же массив из модуля ЛР4. `router.push('/')` вернёт на список.

## Порядок на 4 часа

1. В модуле состояния: массив, счётчик `nextId`, функция добавления.
2. На форме три `v-model` (у числа — `.number`).
3. Функция проверки хотя бы для темы.
4. `@submit.prevent="onCreate"`.
5. После успеха — переход на список, строка видна.
6. Проверить Enter: страница не должна мигнуть белым.
7. Отчёт: три скрина или три коротких абзаца (успех / отказ / F5).

## Сдача

Enter не перезагружает приложение. Короткая тема в таблице не появляется. Новая строка видна в списке. На защите: зачем `.prevent`; где лежит массив; почему после F5 пусто и почему это ещё не катастрофа.

## Частые ошибки

- Забыли `.prevent` — «у меня ничего не работает», на самом деле страница перезагрузилась.
- Пишут `form.title` в скрипте без `.value` — поле всегда пустое или ошибка в консоли.
- `siteId` строка, сравнение с числом потом ломается.
- После создания не переходят на список и думают, что «не добавилось».
- Проверку написали только `if (title)` — один пробел проходит.
