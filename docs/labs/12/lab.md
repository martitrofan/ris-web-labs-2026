## Теория на пару

### Один сквозной сценарий вместо трёх несвязанных демонстраций

Плохая защита: «вот список в Vue (мок), вот POST в Swagger (другая заявка), вот SELECT старого seed». Комиссия не может сверить.

Хорошая: записываете на бумаге `id = 17` и везде проверяете запись с `id = 17`.

Клиент слушает порт **5173**, сервер **5000**. В `.env` ровно тот адрес, что в README. Мок выключен одним флагом.

### Почему вдруг «CORS error»

Браузер считает, что сайт на порту 5173 и сайт на порту 5000 — **разные** места (другой порт = другой origin). По умолчанию он не отдаёт ответ JavaScript с чужого порта. Сервер должен явно сказать: «ответы можно читать сайту `http://localhost:5173`».

Как понять, кто виноват:

- в Network запрос красный, статус вроде «CORS» / нет кода ответа — заблокировал **браузер**. API при этом может быть доступен: откройте тот же URL в Swagger.
- код 500 — виноват сервер, CORS тут ни при чём.

Разрешайте конкретный адрес, не звёздочку `*` на всё интернет.

### Как читать Network

F12 → вкладка Сеть / Network. Нажимаете «Создать» — появляется строка `tickets` (или ваш путь). Смотрите:

- метод (`POST`);
- код (`201`);
- тело запроса (ушла ли тема);
- тело ответа (какой `id` вернули).

Пустой список — `200` и `[]`. Не ищите JSON в ответе `204` (у нас его нет).

Если интерфейс не отображает результат или ошибку: сначала Network, потом консоль браузера, потом логи `dotnet`, потом таблица. Не наоборот и не начинайте с переписывания всего модуля.
