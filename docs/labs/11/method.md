## 3. 401 и 403

### 3.1. Когда 401

`401 Unauthorized` означает: сервер не установил личность.

Примеры:

- нет cookie или `Authorization`;
- токен отсутствует;
- токен испорчен или истёк;
- сессия не существует.

### 3.2. Когда 403

`403 Forbidden` означает: личность известна, но действие запрещено.

Примеры:

- исполнитель пытается создать объект вопреки матрице;
- пользователь назначает исполнителя без нужной роли;
- исполнитель меняет статус записи, назначенной другому.

Спрятанная кнопка не заменяет серверную проверку.

## 4. Пароли

### 4.1. Что запрещено

- открытый пароль в таблице;
- Base64;
- самописный hash;
- пароль живого человека в seed или README.

### 4.2. Что требуется

Используйте password hasher из ASP.NET Identity
или другую проверенную библиотеку с солью и подходящей стоимостью.

В seed можно создать две учебные учётки.
В README разрешено указать их учебные логины и пароли,
если эти данные не используются нигде вне учебного контура.

В PostgreSQL должен лежать длинный hash,
который не равен паролю и не декодируется из Base64.

## 6. Безопасный вывод Vue

Создайте объект с описанием:

```text
<script>alert(1)</script>
```

Показывайте поле обычной интерполяцией Vue:

```html
<p>{{ ticket.description }}</p>
```

Не используйте `v-html` для пользовательского текста.
На экране должны быть видны символы `<script>...`,
но окно `alert` не должно появиться.
